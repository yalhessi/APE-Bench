# Record a named run's inputs beside its generation record

On 25 November 2026 we moved the record of what a named review ran with, its design and the search index it is granted, out of the runner's `run_plan.json`, which a named run no longer writes. It is not in `generation.json` either. It goes in a separate `inputs.json` in the review folder. The file is written once, before the reviewer is dispatched, and the archive carries its digest. [Decision 0002](0002-run-named-reviewers-on-episodes.md)

Two observations decided the placement. First, the earlier named route wrote `generation.json` before `run_plan.json`. A review found that a run interrupted between the two generated on resume and then could not be archived. Second, `generation.json` is write-once. The first version of this change added an `inputs` key to it, which made every record written by the earlier code differ on resume. A separate file keeps the generation record byte-identical across the change. Its preview, message and tools match the pre-change capture exactly. An earlier run that had already sealed its run plan keeps that plan as its record. [Captures and pre-change checks](../../results/pr_review_v5/probes/named-episode-review-2026-11-25/README.md)

The search identity holds only the precedent index the reviewer is granted. An earlier version also hashed the local Zulip corpus whenever one existed. A search review interrupted after acceptance then could not be archived once that corpus appeared, though the reviewer has no Zulip tool. Study runs still seal their inputs in `run_plan.json`, and archiving reads them there.
