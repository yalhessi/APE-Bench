# GitHub Issues

Use `gh` with `--repo yalhessi/APE-Bench` for project issues. A spec describes the intended outcome and how to recognize it. For an experiment, explain what prompted the question and which results would change the next decision. Link a motivating case when available.

Use GitHub sub-issues for parts of a larger task and issue dependencies for work that is blocked. When picking up a proposal from `docs/todo/`, link its original note. Track subsequent work in the issue.

PRs as a request surface: no.
