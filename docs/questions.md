# Questions already answered

One line per question an experiment has answered: the question in plain words, the answer with
its number, and where the evidence lives. **Read the relevant section before proposing a probe, a
design or a run, and after any compaction.** It exists because on 2026-10-13 a probe was proposed
that re-ran the week-old conventions-ceiling result under a new name (`CLAUDE.md`, session
discipline). It is not the record: the probe READMEs, `docs/research/` and the commit bodies are.

Rules:
- Format: `- **<question>** — <answer, with the number> (<date>; <path>)`. `probes/x` means
  `results/pr_review_v5/probes/x`, `research/y.md` means `docs/research/y.md`.
- The question is written so that someone who has never seen the probe's name recognises it; no
  coined condition labels.
- The answer carries the measurement, never a bare verdict.
- Every directory under `results/pr_review_v5/probes/` with a `README.md` or `PROTOCOL.md` appears
  here by name (`tests/mathlib_review/test_tree_lints.py` checks it), and every new probe's
  `PROTOCOL.md` opens with an `## Already answered?` section naming the lines it was checked against.
  Research write-ups with a measurement are listed by hand.
- A line is added in the commit that records the result; a superseded line is edited, not deleted.
- This file lists *results*. An `## Already answered?` check also reads `docs/todo/README.md` for
  open hypotheses and `docs/dead-ends.md`: on 2026-10-16 a plan restated the user's own todo
  (`conventions-nature.md`, studies 2-4) because its check read only this file.

Standing terms: "the solo reviewer" is one whole-PR session with the brief and the tools; "the free
reviewer" is self-hosted DeepSeek-V4.1-Flash; "the 14 held-out PRs" are validation small12's 8 ask
PRs plus the 6 post-cutoff ask PRs (46 asks); "the dev PRs" are the 12 dev held-out ask PRs (47 asks
for the matchers, 23 obligations for the judge); "reach" is asks reached per session on a blind
matcher; "the conventions list" is the maintainers' conventions census (438 entries) in some delivery.

- **Does it matter which harness runs Opus, with the identical prompt?** — Yes: the subagent route is +0.10 on the matcher and +4 obligations on the judge over the project harness (7, 7 against 10-11), a gap as large as DeepSeek over gpt-5.5; same hits per finding (0.09-0.10), fewer findings (77 against 99) (2026-10-01; `probes/claude-models-2026-10-01`, `probes/one-reviewer-table-2026-10-10`)

- **Does the agent harness (APE-Agent, Claude Code, Codex) limit a gpt reviewer?** — No: with gpt-5.2 fixed, the three are within ±0.05 of each other (0.15-0.17 / 0.125 / 0.02 off; 0.21 / 0.25 / 0.29 carried); Codex carried is the highest mean and union but inconclusive by the rule (2026-10-01; `probes/harness-postcutoff-2026-10-01`)

## The reviewer's output and what it reaches

- **Which historical Mathlib requests would RevMate’s Mozilla example selector admit?** — On the 390-PR development export, 396 of 1,140 pass the study-era text predicate. Keeping only inline thread openers leaves 257 on 167 PRs before hunk matching. Of 445 inline requests first rejected for fenced code, 434 contain GitHub suggestions (2026-11-24, [implementation and replay](research/industrial-review-harness-internals-2026-11-24.md#3-treat-the-historical-example-selector-as-part-of-the-reviewer)).

- **How many original findings can we recover when anchoring fails?** — Across 205 completed runs with tracked anchoring reports, 393 of 6,331 findings failed anchoring. All 393 match full local APE submissions by episode, ordinal and claim prefix. The aggregates also record 332 successful reviews with empty findings lists. - **Where does a reviewer miss, when it misses?** — Of 67 residual asks (37 nobody reaches, 30 only Claude), two blind readers per pair: attempted and concluded fine 60%, filed something else on the same object 60%, a convention or mechanism it shows no sign of knowing 37%, decidable by one compile never run 28%, never attempted 6%, verified and withheld 3%; in 63 of 67 every reviewer that missed had read, searched or compiled the object.
