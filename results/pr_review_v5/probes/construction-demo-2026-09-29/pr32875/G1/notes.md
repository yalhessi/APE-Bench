## `Finset.mem_map_equiv` (Mathlib/Data/Finset/Image.lean)
- The PR proof is `simp only [mem_map, Equiv.coe_toEmbedding]; grind`, which the description reports as slower (<10 ms -> 25 ms).
- `grind` alone fails. `simp; grind` compiles. `simp [Equiv.apply_eq_iff_eq_symm_apply]` compiles as one terminal call.
- Finding (advisory): use the single `simp` call, or keep the old proof given the slowdown.

## `Rat.inv_intCast_den_of_pos` (Mathlib/Data/Rat/Lemmas.lean)
- Convention item "drop `ha0`": not a departure. The statement is false for `a ≤ 0` (`inv_intCast_den` gives `natAbs` or 1), so the hypothesis is needed. Dropped.
- Convention item "sibling `inv_intCast_num_of_pos` untouched": that sibling is already `by simp [*]`, so there is nothing to mirror. Dropped.
- `simp [ha0.ne', ha0.le]` leaves `↑a.natAbs = a`. `simp [ha0.ne', Int.natAbs_of_nonneg ha0.le]` compiles. `grind [den_inv, num_intCast]` compiles. `grind [den_inv]` alone fails.
- Finding (advisory): use the explicit terminal `simp` (or a single `grind [...]`), not `simp only` feeding a bare `grind`, which the PR reports as slower.
- I also noticed that `inv_natCast_den_of_pos` could become `by simp [ha0.ne']` (compiled). That is outside this PR's changes, so I did not request it.

## `MeasureTheory.Measure.pi_map_piCongrLeft` (Mathlib/MeasureTheory/Constructions/Pi.lean)
- `Fintype.prod_equiv _ _ _ (congrFun rfl)` is the trivial-`h` case. The docstring of `Fintype.prod_equiv` points to `Equiv.prod_comp` for it.
- `rw [this, pi_pi]; exact e.prod_comp fun i ↦ μ i (s i)` compiles.
- `e.prod_comp _` fails because the `CommMonoid ?m` instance is stuck, so the function must be given explicitly.
- `rw [..., e.prod_comp]` fails to find its pattern because of the let-bound `s'`.
- `Fintype.prod_equiv e _ _ fun _ ↦ rfl` also compiles.
- Finding (advisory): this covers the "direct lemma", "inferable `_` arguments", "finishing tactic" and "merge calls" items together.
