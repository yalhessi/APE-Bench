
## Conventions the maintainers hold

These are conventions Mathlib's maintainers hold when they review, one sentence each: a situation and the form preferred in it. They are stated in general, and none names a place in this PR. Check the changed code against each one. Where it departs from a convention, request the change that convention calls for, as a finding at the place it applies.

- A lemma's name is built from the names of every declaration in its statement, spelled as those declarations spell them, not from informal synonyms, re-tokenisations or omissions.

Under each convention are up to two comments in which a maintainer asked for it on another PR, each with the code it was on. Take the conventions and these examples as the standard for this review: they show what maintainers ask for, and they outrank your own judgement of this code. Where the changed code is in a situation like an example's, file the change its convention calls for, as a finding at that place. None of these is a reason to leave it out: that the code is correct, clear or idiomatic as it stands; that the change is minor or a matter of taste; that this file, its author or its neighbours do it differently; that Mathlib does not require it or a maintainer might not insist on it; that the convention's wording does not quite fit, where the code is like an example's. Where you cannot make or check the change, file it as a question to the author that names the convention and the change. Leave a place unfiled only where a line of the code you quote, or a check you ran, shows it already has the form the convention calls for. In your submission's `message`, list each convention with the places you filed and any place you left, with that line or check. For these conventions this replaces the brief's instructions to emit only what you would actually request and not to raise questions.
