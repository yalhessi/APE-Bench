# Matching reviewer findings to maintainer asks

You are judging, for a research study, which review findings reach which real maintainer requests
on one Mathlib pull request. One anonymous reviewers, `R1` to `R1`, reviewed each PR without
seeing the maintainers' comments. Their labels are shuffled per PR, so `R1` on one PR is not
necessarily `R1` on another.

**Inputs.** They are given below, one section for each:
- `asks_pr<N>.json`: the maintainers' first-round asks on PR N. Each has an `ask_id`, the file
  `path`, `code_at_comment` (the code the comment is attached to, ending at the commented line),
  the `comment`, and the comment it replies to, if any.
- `R1_pr<N>.json` to `R1_pr<N>.json`: each reviewer's findings, a list, indexed from 0.

## For every ask, and each reviewer

Choose one value:

| value | when |
|---|---|
| `reached` | Some finding asks for the same change on the same thing, or for a change that, if the author made it, would satisfy the maintainer's ask. Wording may differ. "Use the existing `foo`" reaches "this is `foo`". |
| `partial` | Some finding is about the same thing and the same kind of issue, but asks for a different change that would not satisfy the maintainer. For example, both say the name is wrong but propose different names, and the maintainer's reason is absent. |
| `no` | Anything else. |

A finding may be a question to the author. Judge it like any other finding: it `reached` the ask when
the change it asks about is the maintainer's change (the author answering yes and making it would
satisfy the maintainer), or when the maintainer's ask is itself that question; it is `partial` when it
asks about the same thing and the same kind of issue without naming the maintainer's change.

Also give the index of the best finding, or `null`.

Judge only whether the finding would lead the author to the maintainer's change. Do not judge
whether the finding is otherwise good.

## Output

Call `submit_matches` once, with two arguments:
- `asks`: one entry per ask, `{"pr": N, "ask_id": "...", "verdicts": [{"reviewer": "R1", "value": "reached|partial|no", "finding": i|null}, ...], "note": "<= 25 words"}`, with a verdict for each of `R1` to `R1`.
- `unmatched`: `{"<pr>": {"R1": <count of R1 findings reaching no ask>, ..., "R1": <count>}}`.

The tool refuses a submission that misses an ask or a reviewer, or names a finding that does not exist, and says which; correct it and submit again.
