# PR 27841: notes (PR-level reviewer)

1. **Wanted / duplicate / trivial.** Nothing in Mathlib at the base commit would use any of the three new lemmas. The only ℕ+-indexed sums are in Cotangent.lean and NatInt.lean. `tsum_int_eq_tsum_neg` is just `(Equiv.neg ℤ).tsum_eq` (Basic.lean:456), which TwoVariable.lean:445 already uses inline. `tprod_zero_pnat_eq_tprod_nat` composes `tprod_pnat_eq_tprod_succ` with `Multipliable.tprod_eq_zero_mul` (NatInt.lean:244). The evenness hypothesis restates `Function.Even` (EvenFunction.lean:26). I found no exact existing duplicate of `tsum_nat_eq_zero_two_pnat`.
2. **Every hunk an improvement?** Making `f` implicit in `tprod_pnat_eq_tprod_succ` is an unannounced breaking change, and the generalisation to `R` does not need it. It forces the Cotangent.lean rewrite to `(f := ...)`. The rest of the Cotangent hunk follows from the casts that change (`Nat.cast_add/one` no longer needed), apart from inlining `h1`, which is minor. No purely typographic hunks.
3. **One thing?** No. It generalises existing API (and adapts Cotangent.lean) and also adds new lemmas, one of them about ℤ rather than ℕ+. Suggest splitting, or at least retitling and describing both parts.
4. **Description.** Empty: no motivation, no mention of the signature changes, no downstream link, no AI-use statement. The title covers only "add pnat lemmas". Filed as blocking.
5. **Finishes the job?** The file states every ℤ-sum result multiplicatively with `@[to_additive]`, as HasProd/Multipliable/tprod triples. `tsum_int_eq_tsum_neg` and `tsum_nat_eq_zero_two_pnat` break both conventions. The even split is done by hand at HasSum level in `hasSum_nat_jacobiTheta` (JacobiTheta/OneVariable.lean:67-78), so a HasSum form would have an immediate use. The PR adds no automation, so there is nothing to test.
6. **Right place?** The pnat and ℤ lemmas belong in InfiniteSum/NatInt.lean. `tsum_int_eq_tsum_neg`, if kept, is a general reindexing fact and belongs beside `Equiv.tprod_eq` in InfiniteSum/Basic.lean, stated for any InvolutiveNeg index (folded into the question 1 finding).
