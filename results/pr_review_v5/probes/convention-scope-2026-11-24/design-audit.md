# What the four reviewers would actually do

25 November 2026. This audit covers the four commands for PR 42184 at commit `999c3900`. Earlier descriptions called these ordinary solo, prior-PR access, automatic conventions and exact conventions. Those labels identify the intended differences. They omit parts of the instructions and the evidence actually supplied. The October scoring replay remains reproducible. Its reviews were already generated. [Commands audited](reproduce-review-reading.md) · [October reading](solo-to-exact.md)

## Who reviews the PR?

There is one Opus 5.5 reviewer per run. APE builds a plan containing specialist prompts, but the solo branch hands the whole episode to a single task. On this case the task gets the title, description, diff, changed files, workspace, tool grant and cutoff. It receives no specialist proposals, delegation responses or other agents' reviews. The two related completed November runs each had one successful attempt, zero nested tokens and no delegated reviewer. Neither is one of the proposed four runs. The evaluator operates after submission. [Solo dispatch](../../../../src/mathlib_review/review/runner.py#L2148) · [Task inputs](../../../../src/mathlib_review/review/runner.py#L531) · [Completed runs](full-tool.md)

**The baseline is already a particular review method.** The shared brief tells the reviewer to examine every target under eight concerns, apply the checklist at every changed declaration, and use Lean to check proposed edits. The task adds a deterministic map of the changed declarations. It asks for a merge verdict, a location and two classifications per finding, with a maximum of 20 findings. The Claude scaffold adds a demand to use tools in every response. These requirements apply to all four conditions. They can affect what a solo reviewer notices or is willing to file. The shared library remains a legitimate source of conventions. On this case the ordinary reviewer opened the file containing the existing sibling lemmas. [Review brief](../gpt52-postcutoff-2026-09-29/brief_G.md#L10) · [User message and filing contract](../../../../src/ape/tasks/lean_tasks/formal_math/review/solo.py#L85) · [Tool-use preamble](../../../../src/ape/scaffolds/prompts.py#L25)

**The reviewer can read its condition name.** The scaffold prints the absolute attempt directory in the first message. The saved ordinary message contained its run name five times. The proposed directories contain `solo`, `history`, `selected` and `exact`. Thus an exact reviewer can learn something about the list's provenance from its path, even though the list heading is identical in the two convention conditions. We observed the visible cue. Its effect on the model's judgment is unknown. Opaque run IDs with the mapping kept outside the reviewer workspace would remove that cue. [Scaffold rendering](../../../../src/ape/scaffolds/claude_code/scaffold.py#L132) · [Run names in the recipe](reproduce-review-reading.md#run-a-matched-example-on-pr-42184)

**Where the brief came from.** APE added the single-session baseline on 12 September to compare one reviewer with the specialist scheduler. The file override arrived on 29 September so researchers could run the same historical control instructions on another model and compare them with instructions that asked it to construct alternatives. The current Opus configuration inherits the control from a later subscription smoke test. Those choices made the old comparison possible. They do not establish that the checklist belongs in a new baseline. [Historical comparison and controls](../gpt52-postcutoff-2026-09-29/README.md#L14) · [Opus smoke configuration](../../../../configs/pr_review_v5_probe_2026_07_08_v1_opus55_G_claude_sub.yaml#L1)

**Which message carries it?** The configuration calls the file `system_prompt_file`. For the proposed Claude Code run, the SDK keeps its own system instructions. APE puts its preamble, the brief, the task and the PR into the first **user** message. The conventions are appended to that message. With APE-Agent, the task brief can enter the system message under the default configuration. Consequently the filename alone cannot establish what either reviewer sees. Removing the file override selects the built-in solo prompt. A minimal baseline needs an explicit short instruction and a check of the assembled message and tool contract. ## What differs before submission?

| Proposed condition | What the check found | What this comparison can establish |
|---|---|---|
| Solo | The checklist, change map and common file, Lean and declaration tools. No prior-comment search tool or catalogue section. | How a single reviewer performs with that complete contract. |
| Earlier comments | The same task message and common tools. The registered tool interface adds only `precedent_search`. The model chooses whether to call it. | The effect of offering search for inline comments by code similarity within this index. |
| Automatic list | The complete solo task text followed by a direction to check each convention and request a change wherever the code departs. Then 25 catalogue sentences. The command reads a saved independent selector output. The selector's reasons, locations and ranking are omitted. | The effect of this particular saved shortlist **and filing instruction**. New samples repeat review conditional on that shortlist. |
| Exact list | The same added instruction and formatting, with two catalogue sentences. Two offline readers assigned the entries after reading the target requests. Only the convention sentences and filing instruction are delivered as the extra section. | How this reviewer responds when supplied the entries behind the recorded asks. The list also signals relevance through its length and specificity. |

On PR 42184 the automatic list already contains **both** exact entries. The shortened-hypothesis rule is second in the delivered list. The sibling-variant rule is thirteenth. The selector itself named `HasSum.nonneg` in its reason for picking the latter. That reason never reached the reviewer. A difference on this PR can arise from interpreting, finding or filing an action among the other 23 rules. It cannot be explained by the selector omitting either reference entry. An earlier scored case, PR 41930, has the complementary pattern: the automatic list contained none of its one reference entry. **The search and catalogue have different source collections.** The 43,736-row search index ends on 31 December 2025. Its interface gives a bounded excerpt of the inline comment and surrounding code. The catalogue was learned from historical asks and includes later PRs. We checked the two original comments that introduced the exact entries for this case. The generalization comment on PR 31984 (2553749321) is absent from the index. The sibling-variant comment on PR 26276 (2160528211) is present. Both date to 2025. A difference between searching and receiving the rules can therefore reflect which source evidence is available as well as how the reviewer uses it. Other indexed comments could still support the same rules. The index uses the comment's creation time. It can contain text edited later. For the five comments actually returned in the earlier ordinary run on 42184, the raw records all give update times before the cutoff. Two of their code hunks exceeded the 1,200 characters stored before the tool cropped its excerpt. That storage limit excluded the end of the original hunk. The reviewer had already tested its weaker-hypothesis change before it called precedent search. This session shows that granting a tool, calling it and basing a finding on its result are distinct. ## Which review gets evaluated?

The four-run recipe uses `kind=solo`. The matcher reads the accepted task result and uses the submitted findings' location, claim, suggested change and severity. The whole-review message, verdict and evidence field are omitted. The later anchoring, merge and verification stages cannot change this particular score. They can change what another consumer receives. In the earlier 42184 pair the guided reviewer submitted two suggestions and both remained in the review channel. Neither survived in the verified channel. The ordinary reviewer had one in each. [Matcher source](../../../../src/mathlib_review/analysis/probes.py#L892) · [Recorded channel comparison](full-tool.md)

For a list-based review, the submitted findings can be the entire public review. In the saved guided submission they were “drop the unnecessary hypothesis” and “add the companion lemma.” The optional message repeated them and explained why a stricter lemma would be false. Scoring the ordered list captured both requests. A general comment can have its own place in that list. [Saved submission and message](full_tool_reviews.json)

The selected expert requests are a reference for recovery. The scorer still has to interpret what would satisfy a request. For example, on PR 30641 a maintainer asked about using `gcongr` at a proof step. The exact reviewer reported that it failed and proposed adding a library-wide tactic rule first. Both archived readers credited the request. A narrower reading of the requested action could change that score without changing any review.
