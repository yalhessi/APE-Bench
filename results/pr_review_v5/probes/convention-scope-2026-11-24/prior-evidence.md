# What the convention-scope pilot adds to earlier review results

October reviewers had already requested the companion lemma on this PR. Some also named it and declined to file it. A separate GPT-5.5 run had already lost both compatible requests from the verified channel. November adds a narrower inspection instruction, an edited input that changes the right action, a natural control, and a replay that identifies where the two requests disappear. The historical maintainer asked both to handle the bottom summation filter and to consider a `HasProd` version. These are two distinct requests on one PR. ## What November adds

November's instruction names neither the PR's missing lemma nor the two historical requests. On the original, the full-tool comparison changed the companion decision from 0/1 to 1/1, with 1 versus 2 submitted findings. In the file-only packets the same question moved it from 0/2 to 1/2, with 2 versus 3 total comments. In both arms 2/2 requested reuse when the edited PR already supplied the lemma, and 2/2 avoided a redundant add or reuse request on natural PR 29857. Both guided original packets identified the generic alternative and disagreed on the value of a named specialization. Thus the pilot adds a check that a cue can lead to reuse or abstention. The controls show no incremental gain over ordinary review. The case was selected with the historical answer known, and no earlier comparison isolates the contribution of the November wording. ## Interpreting the disagreement

An expert deciding on 42184 actually suggested the companion as a tentative local convention, and the author implemented it. The two guided packet reviewers both identified the *same* one-line fallback for a caller with a specified limit. One valued the named shorthand and its use in the submitted theorem. The other found the fallback sufficient. The fallback compiles on the original; the production reviewer also compiled the specialization and its call together. Both technical premises survive. The historical conversation tells us which tradeoff this maintainer chose. The five dated source snapshots trace one local API lineage; the observed stability only dates that practice within the sampled family. [Original maintainer comment](https://github.com/leanprover-community/mathlib4/pull/42184#discussion_r3667804073) · [Guided request](packet-reviews/p83-1.json) · [Guided decline](packet-reviews/p83-2.json) · [Source history](evidence.md)

The study contains one distinct historical PR where the focal action is to **add** the companion. Repetitions on that PR measure variability. Both arms switched to using the lemma when it was supplied, and both passed the separate already-satisfied control. That control was an aggregate equality outside the narrow order-bound trigger. We therefore have an example of a request changing appropriately and a reproducible publication failure. We still lack a case where guidance improves the decision to decline an *absent*, feasible addition. The diff-only scan found just two firings in its two selected cohorts, including 42184; the other, 29254, is available to assess independently. [Protocol and case selection](PROTOCOL.md) · [Screen and exceptions](evidence.md)

A discriminating next comparison would hold time and attention to the same declaration fixed. Give ordinary solo, an equally focused caller check, and the convention-specific question the same independently selected opportunities. Include missing operations experts would request, missing operations they would decline for an explicit reason, and operations already supplied. Measure expert requests recovered at the same reading budget and redundant comments on the controls. A benefit over the equally focused check would support using the convention itself. Separately, the deterministic merge replay can test whether two compatible requests survive while a real “delete” versus “keep and rename” conflict stays unresolved. [Study design](study-design.md) · [Merge replay](full-tool.md)
