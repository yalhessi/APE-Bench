# Can a convention improve a whole-PR review?

On Mathlib PR 42184, the full-tool reviewer asked for the historical change after receiving a short instruction to compare two kinds of callers. Ordinary solo missed it. The two reviews ran under the same pinned model, tools, pass-0 PR description, source snapshot and token limit. This was a known development case; the convention question was written by hand. [Frozen protocol](PROTOCOL.md) · [Exact instruction](intervention.md) · [Historical maintainer request](https://github.com/leanprover-community/mathlib4/pull/42184#discussion_r3667804073) · [Comparison with earlier experiments](prior-evidence.md) · [Position between solo and exact delivery](solo-to-exact.md)

## What the author would receive

The submitted theorem proves that the infinite product of nonnegative factors is nonnegative. The historical maintainer made two requests. The ordinary reviewer recovered one, removing the nonbottom-filter assumption. [First maintainer request](https://github.com/leanprover-community/mathlib4/pull/42184#discussion_r3667779895)

The guided reviewer independently asked for the same generalization and for a lemma establishing the bound on a supplied limit. For a caller holding `HasProd f a L`, the companion directly proves `0 ≤ a`; recovering it from the aggregate theorem via uniqueness would add a Hausdorff assumption. The model checked both changes in one Lean edit.

| Full APE review, one run each | Historical companion requested | Findings in review | Verified / published |
|---|---:|---:|---:|
| Ordinary solo | No | 1 | 1 |
| Same reviewer with the comparison instruction | Yes | 2 | 0 |

The default merge treated the two guided actions on the same declaration as competing. A local replay compiled them together and reproduced the merge demoting both. APE therefore recovered the expert request in its review channel and lost it in its verified channel. The replay also identifies a genuinely conflicting pair that future changes must still catch. ## What we learned about the convention

Two neighboring weak bounds on a total expose a companion for a specified limit. A nearby strict lower bound uses a general binary comparison instead. The same distinction persists across five dated versions of this one API family. Counting those versions, or autogenerated additive forms, as independent votes would exaggerate the evidence. A Lean check confirms the strict client can already use the binary comparison. [Dated source evidence and checks](evidence.md)

A diff-only screen for numeric weak bounds on infinite sums and products fired on 1/390 earlier development PRs and 1/10 July PRs. The earlier hit bounds one fixed geometric series by two, using an existing comparison. The July hit is the known 42184. The narrow family supplies a testable explanation and a controlled regression, with too little independent evidence to justify broad deployment. ## Does the reviewer distinguish add, reuse and already satisfied?

A separate experiment repeated each of six conditions twice. Every session read its instruction and received the original PR text, whole patch and entire changed Lean file. Its file tools had no live Lean environment. We scored the final `findings` array by hand under the frozen rule, then read the private notes. These are two natural PRs and one controlled edit of the first. Repeated runs give a view of variability on these inputs. [Inputs and compilation](fixture-check.md) · [Twelve validated outputs and receipts](packet-reviews/receipt.json)

| Input and focal action | Ordinary solo | Guided solo | Total author comments, ordinary / guided |
|---|---:|---:|---:|
| Original 42184: request the missing companion | 0/2 | 1/2 | 2 / 3 |
| Edited 42184: use the provided companion in the existing proof | 2/2 | 2/2 | 2 / 2 |
| Natural 29857: avoid requesting a companion or uses already in the diff | 2/2 | 2/2 | 0 / 0 |

Neither arm made a duplicate request on either control. All eight reviews of the original or edited 42184 retained the separate request to remove the nonbottom-filter assumption. The guided arm added one author comment across the six packet reviews. Both guided reviews on 29857 identified the public witness lemma and the two corollaries that use it in their notes. No evidence about other possible human requests on 29857 was used. The 12 packet samples used 1,071,138 processed tokens in total. All 12 containment audits were clean and usable.

Both guided original reviews found the same generic alternative, `le_hasProd_of_le_prod`, and reached opposite filing decisions. One argued that the neighboring public lemma also specializes this generic result, and that the new aggregate proof is itself a client. The other judged the one-line generic proof sufficient. Its exact one-line client compiles on the original submission. Its further contention that the file has no use for the specialization is weaker: the actual whole-PR run compiled its use in the submitted theorem. One ordinary reviewer also noticed the missing companion but classified it as extra scope. This distinguishes a reasoned decline from failure to notice the convention. [Guided request](packet-reviews/p83-1.json) · [Guided decline](packet-reviews/p83-2.json) · [Ordinary decline](packet-reviews/p37-2.json) · [Client replay](fixture-check.md)

The pilot met the modest criterion fixed in advance: one additional correct add in the packet comparison, correct use on the edited case, and zero redundant guided requests. The controls were equally successful under ordinary solo. This establishes a case where targeted investigation changed a useful filing. The manually chosen opportunity, shared PR across two cases, small sample, and absence of a length-matched generic or irrelevant cue leave automatic routing, the source of the prompt effect, and general benefit open. The normal full-tool route ran only on the historical original. [Protocol](PROTOCOL.md)

## Decision

Keep 42184 as a regression for two things: updating the action when the interface changes, and preserving compatible requests after submission. Do not expand this particular trigger into a general policy on the strength of the pilot. For independent evidence, the next family is API compatibility when retiring a public name. The earlier study already located 14 development PRs where a missing-alias check would fire with no recorded round-one comment. Use these and existing aliases, moved names and generated names to establish the scope. Then compare ordinary solo, the deterministic compatibility check, and a reviewer that uses the check on a fresh time window. Keep actual expert issues and resolutions, duplicates, and the number of comments per PR visible. [Study design and sampling plan](study-design.md)
